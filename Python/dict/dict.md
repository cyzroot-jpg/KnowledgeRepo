# 1. 字典特性
键值对结构：{"name": "小明", "age": 18}
键唯一：重复赋值会覆盖旧值
键必须可哈希：通常是字符串、数字、元组；列表、字典不能做键
值可以是任意类型：数字、字符串、列表、对象、函数都可以
可变：支持增删改，如 d["x"] = 1、del d["x"]
有序：Python 3.7+ 按插入顺序遍历
查找快：平均时间复杂度 O(1)
支持嵌套：字典里可以放字典、列表等
迭代方便：keys()、values()、items()
空字典为假：bool({}) == False
不是线程安全的：多线程同时修改需要加锁
内存开销较大：用空间换查找速度
只支持浅拷贝：copy() 不会复制嵌套对象

# 为什么「任何字典都能传给 `checkout`」是一个问题？
- 任何 dict 都能传进来，哪怕没有 isbn、title、available
- 类型标注 dict 无法告诉调用方必须包含哪些键、值是什么类型
- 缺少键只会在运行时抛 KeyError，错误暴露得太晚
- 外部可以随意修改 book["available"]，绕过库存规则
- 数据和行为分离，业务规则容易散落在多个函数里

# 面向对象最重要的价值是什么？
不是“多写 class”，也不是“代码复用”，而是：
管理复杂度，让变化局部化。

# 为什么「借书」更适合放在 `Library` 上，而不是 `Book` 上？
因为「借书」不是单本书能独立完成的动作，它需要同时知道：
- 哪本书、还有没有库存
- 哪个会员、是否达到借阅上限
- 借多久、应还日期
- 借阅记录存在哪里
