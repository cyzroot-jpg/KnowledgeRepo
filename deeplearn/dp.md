## 1. FlashAttention
> https://www.zhihu.com/question/611236756/answer/3132304304

标准 Attention 的"分块"藏在 cuBLAS 底层，算法层面操作的是完整大矩阵；FlashAttention 的"分块"暴露在算法层面，是为了让大矩阵能塞进 SRAM，从而避免读写 HBM。

**第一部分：标准注意力 (Standard Attention) —— "来回折腾"**

> 按行分块，一行是一个seq

核心问题：内存墙

标准注意力算法的核心问题是"内存墙"：它将巨大的中间矩阵 S  (4096×4096) 和 P  (4096×4096) 完整地写入 HBM，又读回，产生了巨大的 HBM 流量。

算法流程：
|    阶段   |   步骤   | 数据搬运 (HBM ↔ SRAM)                            | SRAM 内计算                                            | 数据写出 (SRAM → HBM)                  | 说明                                                      |
| :-----: | :----: | :------------------------------------------- | :-------------------------------------------------- | :--------------------------------- | :------------------------------------------------------ |
| **阶段一** | Step 1 | 从 HBM 读取 Q 的一个小块 (64×128) 和 K 的一个小块 (64×128) | 计算 $S_{tile}$ (64×64) = $Q_{tile} \cdot K_{tile}^T$ | 将 $S_{tile}$ 写回 HBM，拼接到完整的 $S$ 矩阵中 | 嵌套循环，直到算完整个 $S$ 矩阵。$S$ 矩阵大小：4096×4096×2 字节 = **32 MB**。 |
| **阶段二** | Step 2 | 从 HBM 读取 $S$ 的一整行 (1×4096)                   | 对该行执行 Softmax，得到 $P$ 的一整行 (1×4096)                  | 将 $P$ 的整行写回 HBM                    | Softmax 是按行操作的。需要循环 4096 次，读完整个 $S$ 矩阵。                 |
| **阶段三** | Step 3 | 从 HBM 读取 $P$ 的一个小块和 $V$ 的一个小块                | 计算 $O_{tile} = P_{tile} \cdot V_{tile}$             | 将 $O_{tile}$ 写回 HBM，拼成最终的 $O$ 矩阵   | 类似阶段一，需要分块完成矩阵乘法。                                       |

> ----
HBM 访问量估算（前向传播）
| 操作          | 计算                                                                   |     数据量     |
| :---------- | :------------------------------------------------------------------- | :---------: |
| 读 Q, K      | $2 \times N \times d = 2 \times 4096 \times 128 = 1{,}048{,}576$ 个元素 |  ≈ **2 MB** |
| 写 $S$       | $N^2 = 4096^2 = 16{,}777{,}216$ 个元素                                  | = **32 MB** |
| 读 $S$       | $N^2 = 4096^2 = 16{,}777{,}216$ 个元素                                  | = **32 MB** |
| 写 $P$       | $N^2 = 4096^2 = 16{,}777{,}216$ 个元素                                  | = **32 MB** |
| 读 $P$ 和 $V$ | 约 $N^2 + dN$                                                         | ≈ **34 MB** |
| 写 $O$       | $dN$                                                                 |  ≈ **1 MB** |

总计
总计约为 133 MB。
这仅仅是一个头（head）的前向传播，数据在 HBM 和 SRAM 之间被反复搬运了多次。


**第二部分：FlashAttention —— “小锅快炒”**

FlashAttention通过分块(Tiling)和在线Softmax(Online Softmax)两大核心技术，将所有计算融合在SRAM中完成，极大地减少了HBM的访问。

其核心循环是：外层循环遍历 K, V 的块，内层循环遍历 Q 的块。

|    阶段    |   步骤   | 数据搬运 (HBM → SRAM)                                   | SRAM 内计算                                                                                                                                             | 数据写出 (SRAM → HBM)                 | 说明                                   |
| :------: | :----: | :-------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------- | :----------------------------------- |
| **外层循环** | Step 1 | 从 HBM 加载 $Q_i$ 块 (64×128) 到 SRAM                    | 在 SRAM 中初始化：$O_i^{(0)} = 0$，$\ell_i^{(0)} = 0$，$m_i^{(0)} = -\infty$                                                                                 |                                   | 遍历所有 $Q$ 块。每个 $Q_i$ 独立处理。            |
| **内层循环** | Step 2 | 从 HBM 加载 $K_j$ 块 (64×128) 和 $V_j$ 块 (64×128) 到 SRAM | ① 计算 $S_{ij}$ (64×64) = $Q_i \cdot K_j^T$<br>② 计算局部最大值 $\tilde{m}_{ij}$ 和局部指数和 $\tilde{\ell}_{ij}$<br>③ 用 $m_i, \ell_i$ **在线更新**全局 Softmax，并更新 $O_i$ | **不写**任何中间矩阵                      | 遍历所有 $K, V$ 块。$S, P$ 矩阵**从不**写入 HBM。 |
| **循环结束** | Step 3 |                                                     | $Q_i$ 处理完所有 $K, V$ 后，得到最终的 $O_i, \ell_i, m_i$                                                                                                        | 将最终的 $O_i$ 和 $\ell_i, m_i$ 写回 HBM |                                      |
|  **返回**  | Step 4 |                                                     |                                                                                                                                                      | 返回最终结果 $O$                        |                                      |

HBM访问量估算（前向传播）：

读 Q, K, V: 各一次，共 3 * N * d = 3 * 4096 * 128 = 1,572,864 个元素 ≈ 3 MB

读写统计量 ℓ, m: 极小，可忽略。

写 O: dN ≈ 1 MB

总计约为 4 MB。与标准注意力的 ~133 MB 相比，HBM流量减少了超过30倍。

**总结**

| 特性            | 标准注意力 (Standard Attention)                          | FlashAttention                     |
| :------------ | :-------------------------------------------------- | :--------------------------------- |
| **核心策略**      | 分步计算，每步结果写回 HBM                                     | 核融合 (Kernel Fusion)，所有计算在 SRAM 内完成 |
| **中间矩阵 S, P** | 完整写入并读回 HBM                                         | 从不写入 HBM，在 SRAM 中计算并丢弃             |
| **数据搬运次数**    | 多（Q, K 读 1 次，S 读写各 1 次，P 写 1 次，P 和 V 读 1 次，O 写 1 次） | 少（Q, K, V 各读 1 次，O 写 1 次）          |
| **HBM 访问量**   | $O(N^2)$                                            | $O(N)$                             |
| **主要瓶颈**      | 内存带宽 (Memory-bound)                                 | 计算能力 (Compute-bound)               |


补充：反向传播中的“重计算”
FlashAttention在反向传播中，为了节省存储中间矩阵 S 和 P 的显存，采用了重计算(Recomputation)策略。

标准注意力：前向时需存储巨大的 P 矩阵 (NxN) 在HBM中，供反向传播使用。

FlashAttention：前向时只存储 Q, K, V 以及每个块对应的统计量 m, ℓ (大小仅为O(N))。在反向传播时，它会重新从HBM加载 Q, K, V 块到SRAM，并利用存储的统计量，重新计算出对应的 S 和 P 矩阵块，以计算梯度。

这是一种典型的用计算换内存的策略，虽然增加了少量计算，但极大地降低了HBM的访问量和显存占用。

## 2. KV Cache

| 步骤               | 无 KV Cache（灾难）           | 有 KV Cache（标准做法）                       |
| :--------------- | :----------------------- | :------------------------------------- |
| **输入**           | 全部 $N+1$ 个 token         | 只有**最新 1 个** token                     |
| **计算 Q**         | 算全部 $N+1$ 个 token 的 Q    | 只算**新 token** 的 Q（1 个）                 |
| **计算 K, V**      | 算全部 $N+1$ 个 token 的 K, V | 只算**新 token** 的 K, V（1 个），之前的从 cache 取 |
| **Attention 规模** | $(N+1) \times (N+1)$     | $1 \times (N+1)$（新 token 查所有历史）        |
| **复杂度**          | $O(N^2)$ 每步，越来越慢         | $O(N)$ 每步，线性增长                         |
