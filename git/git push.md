# Git Push 笔记

## 1. 基本作用

`git push` 把本地仓库中**已提交（commit）**的内容上传到远程仓库（如 GitHub、GitLab），让远程分支更新到和本地一致。

```bash
git push <远程名> <本地分支>:<远程分支>
git push origin main        # 把本地 main 推到远程 main
git push origin main:dev    # 把本地 main 推到远程 dev
```

## 2. 它传输什么

- **提交对象（commit）**：新的 commit 及其父提交
- **关联的文件快照（tree/blob）**：commit 引用的实际文件内容
- **分支/标签引用**：更新远程对应的 ref 指针

注意：push **不会**自动包含未 commit 的改动（工作区、暂存区内容不会被推送）。

## 3. 核心机制

- push 本质是"对比后传输缺失对象"。Git 先算出远程没有的 commit，再打包上传。
- 必须是**快进（fast-forward）**：远程分支的新位置必须是本地分支的祖先，否则会被拒绝，需先 `git pull` / `rebase` / `merge` 解决冲突。
- 推送后更新远程的跟踪引用（`origin/main`）。

## 4. 常见用途 / 形式

```bash
git push                    # 推送当前分支到其上游(upstream)
git push -u origin main     # 首次推送并设置上游跟踪
git push --all              # 推送所有分支
git push --tags             # 推送标签
git push origin --delete x  # 删除远程分支 x
git push --force            # 强制覆盖远程（危险，会改写历史）
git push --force-with-lease # 更安全的强制推送
```

## 5. 常见问题

- **rejected (non-fast-forward)**：远程有你本地没有的提交，先 `git pull` 再推。
- **force push**：会覆盖远程历史，多人协作时可能导致他人提交丢失，慎用。
- **权限不足**：没有远程仓库的写权限或未配置认证（SSH key / token）。

## 6. commit 对象与父提交

这是 Git 的核心数据结构问题。Git 里每个 commit 是一个"对象"，它通过**指针**串成一条链，这条链就是历史。

### 一个 commit 对象里有什么

- 一个指向**文件快照**的指针（tree 对象，记录当时所有文件内容）
- 作者 / 提交者信息、时间
- 提交说明
- **一个或多个指向父 commit 的指针**（parent）

### "父提交"是什么意思

父提交就是**这个 commit 的上一个 commit**，即它是基于哪个版本改出来的。

```
A ← B ← C
```

- `C` 是新的 commit
- `C` 的父提交是 `B`
- `B` 的父提交是 `A`

每个 commit 都记录自己的父提交，于是从最新的 commit 顺着父指针往回走，就能还原出**完整历史**。

### 为什么 push 要传"新 commit 及其父提交"

因为远程可能只缺最新几个 commit。push 时 Git 会：

1. 找出远程没有的 commit（比如远程停在 `B`，本地到了 `C`）
2. 把 `C` 传过去
3. 但 `C` 里存的是"父提交是 B"的指针，远程必须能对上 `B` 这个对象，否则链就断了

所以如果 `C` 的祖先（B、A...）远程也缺失，Git 就必须把它们一起打包传过去，才能保证历史的完整性。

### 特殊情况：多个父提交（merge）

普通 commit 有 1 个父提交。**合并（merge）产生的 commit 有 2 个父提交**，代表它同时继承了两个分支：

```
      C
     / \
A ← B   M   ← M 有两个父：B 和 C
     \ /
      ...
```

### 小结

- **commit 对象** = 一次快照 + 元信息 + 父指针
- **父提交** = 上一次提交，靠它形成历史链
- push 需要"新 commit 及其父提交"，是为了让远程能接上已有的历史，保持链条不断。

## 7. push 到底推了哪些提交

准确说法：**只推送远程"还没有"的提交，而不是本地全部提交。**

### 举例

假设远程已有 `A ← B`，本地是 `A ← B ← C`：

```bash
git push
```

- 远程已有 A、B → **不会重传**
- 只传新的 C（以及它缺失的祖先，如果有的话）

如果本地是 `A ← B ← C`，远程是 `A`：那会传 `B`、`C`。

### 关键点

1. **不重复传已有对象**：Git 会先比对，远程已有的 commit 不传，只补缺失的。
2. **只推当前分支**：`git push` 默认只推当前分支，其他分支的提交不会自动推。要推所有分支用 `git push --all`。
3. **未 commit 的改动不推**：工作区 / 暂存区的修改必须先 commit 才会被推送。
4. **只有连通到该分支的提交**：推的是从被推分支能回溯到的历史链上的提交。

### 结论

> push 把**本地分支上、远程缺少的那部分提交历史**上传到远程，让远程分支更新到和本地一致。

如果本地和远程已经有相同的提交，push 会提示 `Everything up-to-date`。

---

## 8. 一句话总览

- **commit**：把改动存到本地历史。
- **push**：把这份历史同步到远程，让别人能看到和协作。
- push 只传**远程缺少的那部分提交**，并保持"新 commit → 父提交 → ..."的历史链条完整。
